## 1. Goal and acceptance criteria

From the issue body:

- [ ] Explicit `type:` keys for GS, MPC, SLC, WBC, MA in
      `ws/src/controllers/config/mit_controller_sim_go2.yaml` and
      `ws/src/controllers/config/mit_controller_real_go2.yaml`
- [ ] Defaults match current stock Go2 behavior exactly
- [ ] Documented in param comments and modularity docs
- [ ] Launch still works with `sim:=go2` / `real:=go2`

From the issue comment of 2026-07-27 (**this changes what "done" means — it is not optional**):

- [ ] `scripts/joy_to_target.py` sets `gs.type` (`simple_gait` / `adaptive_gait`) instead of the
      legacy `gait_sequencer` (`"Simple"` / `"Adaptive"`)
- [ ] Sequencer switching from the joystick still works with explicit `type:` keys in the YAML
- [ ] No caller in the tree sets `gait_sequencer` or `ma_mode` at runtime after this PR

Why the comment exists: M2.4's legacy bridge re-derives `gs.type` whenever `gait_sequencer` is
set at **runtime** ([mit_controller_node.cpp:345-354]). If the YAML carries an explicit
`gs.type` but the joystick still writes `gait_sequencer`, the first Y-press silently overwrites
the YAML's choice. Explicit YAML selection and joystick switching are mutually exclusive until
the joystick speaks the new vocabulary — so both must land in one PR.

**Explicit non-goals** (respect the milestone plan):

- Do NOT remove the legacy bridge — neither the declare-time derivation
  (`include/stage_selection.hpp`, `mit_controller_node.cpp:293-304`) nor the runtime
  re-derivation branch (`mit_controller_node.cpp:345-354`). That deletion is #23 (M5.4), *after*
  M3/M4 and the M5.3 checklist. This PR's job is to make the bridge **dead weight** (nothing in
  the tree exercises it), not to delete it. The ULab YAMLs also still rely on the declared
  defaults.
- Do NOT touch `mit_controller_{sim,real}_ulab.yaml` — the issue is Go2-scoped; ULab keeps
  working through the bridge defaults (`gs.type=simple_gait`, `wbc.type=inverse_dynamics` via
  `WBCTypeForBuild`, `model_adaptation.type` from `ma_mode`).
- Do NOT add a `contact_logic.type` key — the contact FSM is still host code until #12 (M3.1).
- Do NOT add `bio_gait` anywhere — that is #16 (M4.1); it will become just another `gs.type`
  value with no schema change, which is exactly why this schema is worth ratifying now.
- No C++ behavior changes. `pipeline_host.md` §9 promises "#10: writes the `*.type` keys into
  the Go2 YAMLs; **no host change needed**". The only C++ touched is comments (§4 step 5) and a
  new test (§5).

## 3. Design decisions (and why)

1. **Ratify the M2.4 vocabulary unchanged** — `gs.type`, `mpc.type`, `slc.type`, `wbc.type`,
   `model_adaptation.type`, string-valued, naming the pluginlib class. `stage_loading.md` §4
   gives M2.5 the right to rename; do not use it. The names are already load-bearing (host,
   tests, docs, PR #33), the flat-dotted spelling matches how every other stage param is
   written, and renaming now would buy nothing but churn. This plan *is* the ratification —
   record it in the docs (§4 step 6).

2. **YAML spelling: nested maps** (rclcpp flattens to the dotted names):
   ```yaml
   gs:
     type: simple_gait          # gait sequencer: simple_gait | adaptive_gait
   mpc:
     type: acados_mpc           # model predictive controller: acados_mpc
   slc:
     type: bezier_swing         # swing leg controller: bezier_swing
   wbc:
     type: wbc_arc_opt          # whole body control: wbc_arc_opt (go2 build) | inverse_dynamics (ulab build)
     inverse_dynamics: ...      # (existing sub-maps stay)
     arc_opt: ...
   model_adaptation:
     type: kf_adaptation        # model adaptation: kf_adaptation | rls_adaptation
   ```
   Values **identical in both Go2 YAMLs** and identical to the bridge-derived defaults in the
   §2 table — that is the "defaults match current stock Go2 behavior" criterion. Nested maps
   (rather than literal `gs.type:` flat keys) match the file's existing style (`raibert:`,
   `wbc:`, `adaptive_gait_sequencer:`) and give each stage a natural home for future keys (#13's
   WBC profile, #21's parameter reference).

3. **Drop `ma_mode: 0` from the two Go2 YAMLs** in the same change. With an explicit
   `model_adaptation.type` present, `ma_mode` becomes a decoy: flipping it to `1` would change
   nothing (explicit type wins), which is precisely the silent-mismatch trap the issue comment
   describes for `gs.type`. Two spellings of the same choice must not coexist in one file. The
   parameter stays *declared* in the host (ULab YAMLs and out-of-tree configs still use it;
   removal is #23). The other `ma_*` keys (`ma_forgetting_factor`, noise vectors, …) are stage
   parameters, not selectors — keep them.

4. **`joy_to_target.py` speaks plugin class names natively.** Replace the internal
   `"Simple"`/`"Adaptive"` vocabulary with `simple_gait`/`adaptive_gait` throughout (state init
   `:54`, both branch comparisons, both Y-press assignments `:313/:325`) and send
   `Parameter(name="gs.type", value=...)` at both send sites (`:343`, `:381`). One vocabulary,
   no translation table, and grep for `"Simple"` in the script coming up empty is itself the
   review check. This is also a micro-improvement on the switch path: setting `gs.type`
   directly skips the bridge's re-derive hop (one fewer `set_parameter` round-trip and one fewer
   parameter event before the reload starts).

5. **Keep the runtime re-derivation branch in the host, untouched.** After this PR it is
   exercised by nothing in the tree, but out-of-tree users (and anyone on an older
   `joy_to_target`) still get correct behavior during the M3/M4 window. Update its comment —
   it currently says "This is how joy_to_target still switches … until #10 (M2.5)", which
   becomes false the moment this lands. New comment should say: as of M2.5 no in-tree caller
   uses this; it survives for out-of-tree callers until #23 deletes it.

6. **Known gap, explicitly out of scope (state it in the PR):** `joy_to_target` hard-codes its
   initial sequencer state (`simple_gait` after this PR). If a user edits the YAML to
   `gs.type: adaptive_gait`, the joystick's idea of the active sequencer starts out wrong until
   the first Y-press. This is a **pre-existing** mismatch (the script never read
   `gait_sequencer` either); fixing it properly means querying
   `/mit_controller_node/get_parameters` for `gs.type` at startup. Do not do it here — it adds
   a service dependency and a timeout path to a safety-relevant teleop script and belongs in
   its own change (natural home: #21/#22 in M5, or a dedicated issue). Mention it in the PR
   body under "Known limitations".

## 5. Tests

**New: `test/test_go2_yaml_stage_selection.cpp`** (gtest, `BUILD_TESTING` only) — turns the
issue's "defaults match current stock Go2 behavior" from a review claim into a pinned property:

- Locate both shipped YAMLs via
  `ament_index_cpp::get_package_share_directory("controllers") + "/config/…"` (they are
  installed, `CMakeLists.txt:629`).
- Parse with `rclcpp::parameter_map_from_yaml_file` and take the `mit_controller_node` entry.
- Assert, per file:
  1. all five `*.type` keys are present, string-typed, non-empty (spelled via the
     `stage_selection::k*TypeKey` constants — a key rename then breaks this test, which is the
     point: M2.5 froze the vocabulary);
  2. each value **names a declared plugin** for its stage base
     (`StageLoader<I>{stage_plugin_bases::k…}.DeclaredClasses()`, same technique as
     `test_stage_selection.cpp:40-42`) — for `wbc.type` check against the build-flavour base so
     the test is correct under both `ROBOT_NAME`s;
  3. the values equal the bridge-derived defaults (`simple_gait`, `acados_mpc`, `bezier_swing`,
     `WBCTypeForBuild(USE_WBC)`, `kf_adaptation`) — this is the behavior-match criterion; #16
     or a deliberate default change must edit this test consciously;
  4. the legacy selectors `gait_sequencer` and `ma_mode` are **absent** from both Go2 files —
     the two-spellings trap of §3.3 cannot creep back.
- Guard the test to skip (with a message) if the share directory lacks the files, so
  `colcon test` from an un-installed tree fails loud-and-clear rather than cryptically.

**Existing tests** must pass unchanged — `test_stage_selection` (derivation still compiled and
correct), `test_stock_plugins`, `test_stage_loader`, `test_plugin_discovery`,
`test_stage_contracts`. No existing test asserts anything about the YAML files or
`joy_to_target`, so no updates are expected; if one fails, that is a real regression.

There is no Python test infra for `scripts/`; `joy_to_target` is covered by the §8 human test
plan (it is the M2.6 acceptance path anyway).

## 6. Performance

No performance loss is possible by construction, and the PR body should say exactly why:

- **Control loops:** zero C++ statements change (§1 non-goals; only comments and a test). The
  loop bodies M2.4 kept byte-identical stay byte-identical.
- **Bring-up:** rclcpp parses five more YAML keys and the `declare_parameter` calls now find
  overrides instead of using defaults — nanoseconds, once, before any timer exists.
- **Joystick sequencer switch:** strictly cheaper. The legacy path was
  `set(gait_sequencer)` → event → host `set_parameter(gs.type)` → second event → reload;
  the new path is `set(gs.type)` → event → reload. Same off-loop
  load → `UpdateTarget` → swap-under-lock reload (`mit_controller_node.cpp:448-464`), one fewer
  round-trip before it starts. The swap still happens outside the control loops; a failed load
  still keeps the running sequencer.
- The new test adds test-time cost only.

## 9. Risks & edge cases (check during implementation)

- **Ordering inside one `SetParameters` request** (STAND-while-Adaptive sends
  `simple_gait_sequencer.gait` + `gs.type` together): the host processes changed params in
  order and coalesces into a single `gait_update` reload after the loop
  (`mit_controller_node.cpp:339-465`); the fresh sequencer reads the just-set gait from the full
  param map. Same coalescing the legacy path relied on — verify once in sim (test plan item 5).
- **`wbc.type` vs the `wbc.*` runtime router** (`mit_controller_node.cpp:382`): a *runtime* set
  of `wbc.type` routes to `wbc_->SetParameter`, which warns "not yet supported" — correct until
  #13 (M3.2). Declare-time YAML value is unaffected. No action, just don't "fix" it.
- **ULab + shared joystick script:** `joy_to_target.py` is launched for ULab too. The migration
  is safe there: `adaptive_gait`/`simple_gait` are declared for every build flavour
  (`test_stage_selection` pins this), and the ULab YAMLs' missing `gs.type` just means the
  bridge default (`simple_gait`) — the same sequencer the legacy path selected. State this in
  the PR body.
- **Do not let the implementing agent "clean up" the bridge** — the temptation is real since
  this PR makes it dead code in-tree. Deleting it here breaks ULab YAMLs' `ma_mode` and any
  out-of-tree config, and collapses the carefully staged #23. The non-goal in §1 is load-bearing.
