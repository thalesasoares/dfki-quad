## 1. What the issue asks

Wire `BioGaitSequencer` as a selectable plugin — today it is compiled but not constructible from
params. Acceptance criteria, mapped:

| AC | Where it lands |
|---|---|
| Bio gait exported as plugin and listed in YAML options | new `bio_gait` wrapper in `src/plugins/gait_sequencer_plugins.cpp` + entry in `plugins/gait_sequencer_plugins.xml` + vocabulary comment in the Go2 YAMLs |
| Selectable via stage `type:` without editing host source | already guaranteed by the M2.4 host: `gs_loader_.Load(...)` resolves any declared class ([mit_controller_node.cpp:538](../../ws/src/controllers/src/mit_controller_node.cpp)); **zero host changes** — `pipeline_host.md` §"issue map" line 216 promised exactly this ("Becomes a `gs.type` value; no host change needed") |
| Loads successfully; basic smoke in sim | `test_stock_plugins.cpp` load+Init+cycle test (automated) + manual Go2 sim smoke (§6 test plan) |
| Documented in contributor / param docs | `stock_plugins.md`, `stage_loading.md`, YAML comments (§4.7). The real contributor guide is #18 (M4.3) and the full param reference is #21 (M5.2) — this PR updates the docs that exist today and leaves those issues their scope |

Everything the wrapper needs already exists:

- `BioGaitSequencer` implements the frozen `GaitSequencerInterface` in full, including
  `UpdateModel` and a `SetParameter` that returns `false`
  ([bio_gait_sequencer.hpp:14-55](../../ws/src/controllers/include/mit_controller/bio_gait_sequencer.hpp)).
- `GS_Type::BIOINSPIRED = 2` exists ([gait_sequencer_types.hpp:3](../../ws/src/controllers/include/mit_controller/gait_sequencer_types.hpp)) and `GetType()` returns it (bio_gait_sequencer.cpp:177).
- `bio_gait_sequencer.cpp` is **already compiled into `libgait_sequencer_plugins`**
  ([CMakeLists.txt:495-502](../../ws/src/controllers/CMakeLists.txt)) precisely so #16 would not
  rot — see the comment at CMakeLists.txt:489-494. No build-system source change is needed.

## 2. Long-term context (why this shape)

- **M4 exit criterion** is "add-stage path proven … Bio gait selectable". M4.1 is the proof that a
  stage that *never had a host factory branch* can join the pipeline purely through the M2 plugin
  machinery: XML entry + wrapper class + YAML value. Keep the diff exactly that small — it is the
  template #17 (example plugin) and #18 (contributor guide) will point at.
- **#18 (M4.3)** will document "how to add a stage implementation" — the bio wrapper should
  therefore stay a textbook thin adapter (plugin_lifecycle.md §4, Option B) with nothing clever
  in it.
- **#19 (M4.4)** adds a launch overlay to swap one stage. Do **not** add launch-file machinery or a
  `gs.type` launch argument here; the manual smoke selects bio by editing the YAML or via
  `ros2 param set` (both already supported).
- **#23 (M5.4)** deletes the legacy `gait_sequencer` bridge. Therefore **do not extend
  `GaitSequencerTypeFromLegacy` with a `"Bio"` mapping** (decision D2 below) — growing a
  scheduled-for-deletion shim would move against the milestone plan.
- **#21 (M5.2)** writes the full parameter reference; this PR only needs the vocabulary comments
  and `stock_plugins.md` accurate.

## 3. Design decisions (settle these before coding)

- **D1 — plugin class name: `bio_gait`.** Pre-agreed: `stock_plugins.md` §1 ("`bio_gait`
  (`BioInspiredGait`) is deliberately **not** exported here — issue #8 defers it to M4.1") and the
  XML comment (gait_sequencer_plugins.xml:7-8) both reserve the id.
- **D2 — no legacy bridge.** The pre-plugin host factory `GetGaitSequencerFromParams` never had a
  `"Bio"` branch (verified: `git grep Bio 419870c -- ws/src/controllers/src/mit_controller_node.cpp`
  is empty — bio was compiled but unreachable from params, which is this issue's premise), and
  `test_stage_selection.cpp:60` pins `GaitSequencerTypeFromLegacy("Bio") == "Bio"` as an *unknown*
  pass-through. Keep it that way: bio is selectable only through the ratified `gs.type: bio_gait`
  spelling. A config that writes `gait_sequencer: Bio` passes through to the loader and fails fast
  listing declared plugins — correct, since there is no legacy behaviour to preserve. Note: the
  claim in `stage_loading.md` line 133 that the legacy parameter accepted `"Bio"` is inaccurate;
  fix it in the doc pass (§4.7).
- **D3 — Go2 default stays `simple_gait`.** The issue asks for *selectable*, not *default*.
  `test_go2_yaml_stage_selection.cpp` pins the shipped defaults (its own comment, line 21, names
  "#16's bio_gait" as the kind of change that must edit the test consciously — we are not making
  that change). Zero behaviour change on the stock path.
- **D4 — zero host changes.** Bring-up load (mit_controller_node.cpp:538) and the runtime
  `gs.type` rebuild-and-swap (mit_controller_node.cpp:487-492) are already class-name-generic.
  If any host edit seems needed, the design is wrong — stop and reconsider.
- **D5 — no new parameters.** The `BioGaitSequencer` constructor consumes exactly the *shared*
  gait-sequencer keys the other two wrappers read (`gs_shoulder_positions`, `raibert.*`,
  `fix_standing_position`, `fix_position_*_threshold`, `early_contact_detection`) — it is the
  `SimpleGaitSequencerPlugin::Init` minus the `Gait`/`simple_gait_sequencer.*` handling. Its gait
  choice is internal (`BioGaitDatabase` driven by Froude number). Do not invent a
  `bio_gait_sequencer.*` namespace with nothing in it.
- **D6 — joystick out of scope.** `scripts/joy_to_target.py` cycles `simple_gait`/`adaptive_gait`
  on Y (lines 318, 330) and tracks the loaded sequencer to route gait-button presses. Adding bio to
  the joystick UX is polish that belongs with #19/M5, not with the plugin-export proof. Note in the
  PR: after a manual `ros2 param set gs.type bio_gait`, the joy script's internal tracking is stale
  — a **pre-existing** limitation it documents itself for YAML-edited `adaptive_gait`
  (joy_to_target.py:54-59). Also note: bio has no runtime-tunable params (`SetParameter` returns
  `false`), so gait buttons are no-ops while bio is loaded — expected, not a bug.

## 4. Implementation steps

### 4.1 `src/plugins/gait_sequencer_plugins.cpp` — the wrapper

Add `class BioGaitSequencerPlugin final : public StagePlugin<GaitSequencerInterface>` alongside the
two existing wrappers, mirroring `SimpleGaitSequencerPlugin` exactly:

- `Init(StageInit init)`: `Require` `gs_shoulder_positions` (+ the existing length check via the
  shared `ShoulderPositions` helper — reuse it, do not duplicate), then
  `impl_ = std::make_unique<BioGaitSequencer>(GetOr<double>(init, "raibert.k", 0.03),
  ShoulderPositions(shoulder_flat), std::move(init.state), std::move(init.model),
  GetOr<int64_t>(init, "raibert.filtersize", 20), GetOr<bool>(init, "raibert.z_on_plane", false),
  Require<bool>(init, "fix_standing_position"), GetOr<double>(init,
  "fix_position_distance_threshold", 0.1), GetOr<double>(init, "fix_position_angular_threshold",
  0.26), GetOr<double>(init, "fix_position_velocity_threshold", 0.1), Require<bool>(init,
  "early_contact_detection"))`. Same required-vs-defaulted split as the neighbours — the shared
  keys must keep one spelling and one strictness across all three wrappers.
  Watch the ctor's parameter order: `k` comes **first** (before shoulders), unlike nothing else —
  read [bio_gait_sequencer.hpp:16-26](../../ws/src/controllers/include/mit_controller/bio_gait_sequencer.hpp) while writing it.
  Note `raibert_filtersize` is `unsigned int`: pass the `GetOr<int64_t>` result the same way
  `SimpleGaitSequencerPlugin` does (implicit narrowing there compiles under `-Werror` because the
  ctor takes `unsigned int`; match whatever cast/spelling the neighbour uses so the file stays
  uniform).
- Forwarders: the same seven one-line overrides the other wrappers have (`GetGaitSequence`,
  `UpdateState`, `UpdateModel`, `UpdateTarget`, `GetGaitState`, `GetType`, `SetParameter`).
- `PLUGINLIB_EXPORT_CLASS(stock_plugins::BioGaitSequencerPlugin, StagePlugin<GaitSequencerInterface>)`
  at the bottom with the other two.
- Include `mit_controller/bio_gait_sequencer.hpp`.
- Update the file-header comment: delete lines 11-12 ("bio_gait is deliberately absent…") and add a
  sentence noting bio's `Init` is **new** code (no host factory branch to mirror — see §4.7 note on
  `stock_plugins.md` §2's provenance table).

## 5. Performance (explicitly: why there is no regression)

State these in the PR; they are all verifiable by inspection:

1. **Stock path untouched.** Go2 default remains `simple_gait` (D3); the host is unmodified (D4);
   `test_go2_yaml_stage_selection.cpp` proves the shipped configs select the same stack as before.
2. **No new code in any hot loop.** The only runtime cost of bio-when-selected is the same single
   virtual-forward per interface call every stock wrapper already pays — the pattern the M2.6 (#11)
   sim regression validated on-robot.
3. **No new compilation into the .so, no link-line change.** `bio_gait_sequencer.cpp` has been
   compiled into `libgait_sequencer_plugins` since M2.4 (CMakeLists.txt:499) with the same
   directory-scope `-Ofast`/`-O3` as the node (stock_plugins.md §4 "Same optimisation as the
   node") — this PR adds a wrapper class to an existing TU and an XML entry. Library load
   (dlopen) cost is unchanged in any measurable way.
4. **Runtime `gs.type` switch stays off-loop.** The existing rebuild path
   (mit_controller_node.cpp:487) constructs the fresh sequencer *before* taking the lock; bio rides
   it unchanged.

## 8. Risks / open points for the implementer

- **`-Werror` in the plugin TU**: `bio_gait_sequencer.cpp` already compiles under the plugin flags,
  so the only new warning surface is the wrapper itself — keep it as boring as its neighbours.
- **Ctor argument order** (`k` before shoulders; see §4.1) — the one place a silent transposition
  could compile and misbehave; the smoke test's "stands and walks" step is the catch.
- If `test_stage_loader.cpp` turns out not to pin the declared-id set (stock_plugins.md §5 says it
  does), don't add such a pin there — `test_plugin_discovery.cpp:105` already owns that assertion;
  just fix the doc sentence instead.
- The `mitcontroller` potato-sim harness (CMakeLists.txt:362-398) links bio directly and is
  untouched — do not "clean it up" in this PR.
