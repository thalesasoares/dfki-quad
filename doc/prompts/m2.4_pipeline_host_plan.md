## 1. Goal and acceptance criteria (from issue #9)

Turn `MITController` (the ROS node in
`ws/src/controllers/src/mit_controller_node.cpp` + `include/mit_controller_node.hpp`) into a
**thin pipeline host**: it keeps timers, mutexes, callback groups, ROS pub/sub/services, and
**plugin ownership**, and constructs **no concrete algorithm** anymore.

- [ ] Host loads all five stages exclusively via `StageLoader` (M2.2)
- [ ] No concrete algorithm factory `if/else` left in the host for stock stages
- [ ] MPC @ 100 Hz (`MPC_CONTROL_DT`), SLC + control loop @ 500 Hz (`SWING_LEG_DT`/`CONTROL_DT`),
      model adaptation @ 100 Hz (`MODEL_ADAPTATION_DT`) preserved
- [ ] Mutually exclusive callback groups + 4-thread `MultiThreadedExecutor` preserved
- [ ] Outer topics unchanged: `/quad_control_target`, `/quad_state`, `/leg_cmd` / `/leg_joint_cmd`
      (and all diagnostic topics: `solve_time`, `wbc_solve_time`, `gait_state`, `gait_sequence`,
      `controller_heartbeat`, `quad_model_update`, `quad_model_debug`, …)
- [ ] **No performance regression** in the control loops (see §6 — the steady-state loop bodies
      must be byte-for-byte untouched except for the pointer types they call through)

**Explicit non-goals** (respect the milestone plan):
- Do NOT extract the early/late/lost-contact FSM from `ControlLoopCallback` — that is #12 (M3.1).
- Do NOT de-template `WBCInterface` or make the WBC command type a runtime choice — that is #13
  (M3.2). Keep the compile-time `WBCType` = `std::conditional<USE_WBC, …>` exactly as is.
- Do NOT touch the Go2 YAML files' schema — that is #10 (M2.5). M2.4 must keep today's YAML +
  launch args working unchanged (see §3).
- Do NOT wrap `BioGaitSequencer` as a plugin — that is #16 (M4.1).
- The standalone potato-sim harness `src/mit_controller/mit_controller.cpp` is out of scope.

## 2. Current state (what the implementing agent will find)

- Host factories to delete: `GetGaitSequencerFromParams()` (mit_controller_node.cpp:592-707,
  Simple/Adaptive branches), inline MPC construction + `mpc_solver` string→enum `if/else`
  (:435-466), MA `switch (ma_mode)` (:472-501), SLC construction (:503-508), the `create_wbc`
  generic lambda (:516-548). Every one of these bodies was already transcribed into a stock
  plugin `Init` in M2.3 (`src/plugins/*_plugins.cpp`) — do not re-derive them, they are the
  reference for behavioral equivalence.
- Plugin machinery available: `mit_controller/stage_plugin.hpp` (`StagePlugin<I>`, `StageInit`,
  `StageInitError`), `mit_controller/stage_loader.hpp` (`StageLoader<I>`, `StageLoadError`,
  `stage_plugin_bases::k*`). Contracts: `doc/modularity/plugin_lifecycle.md`,
  `doc/modularity/stage_loading.md`.
- Declared stock plugin class names (from `plugins/*.xml`):
  | Base | Class names |
  |---|---|
  | `StagePlugin<GaitSequencerInterface>` | `simple_gait`, `adaptive_gait` |
  | `StagePlugin<MPCInterface>` | `acados_mpc` |
  | `StagePlugin<SwingLegControllerInterface>` | `bezier_swing` |
  | `StagePlugin<WBCInterface<JointTorqueVelocityPositionCommands>>` | `wbc_arc_opt` |
  | `StagePlugin<WBCInterface<CartesianCommands>>` | `inverse_dynamics` |
  | `StagePlugin<ModelAdaptationInterface>` | `kf_adaptation`, `rls_adaptation` |
- `StageLoader::Load` returns `pluginlib::UniquePtr<StagePlugin<I>>` (`StageLoader<I>::PluginPtr`)
  — host members must be that type, **not** `std::unique_ptr<I>` (deleter is part of the type).
- **Declaration order is load-bearing**: each `StageLoader` member must be declared *before* the
  `PluginPtr` it produces (members destroy in reverse order; destroying a `ClassLoader` before
  its instances leaves dangling vtables). `stage_loader.hpp:115-120` documents this.

## 3. Design

### 3.1 Stage selection keys + legacy bridge (the M2.5 seam)

Declare five new string parameters using the vocabulary already proposed in
`stage_loading.md` §4: `gs.type`, `mpc.type`, `slc.type`, `wbc.type`, `model_adaptation.type`.
Their **defaults are computed from today's legacy parameters**, so current YAMLs and launch
files keep working with zero edits (M2.4 acceptance) until M2.5 writes explicit keys:

| Key | Default derivation |
|---|---|
| `gs.type` | from legacy `gait_sequencer` param: `"Simple"`→`simple_gait`, `"Adaptive"`→`adaptive_gait`; any other value passes through **verbatim** so the loader fails loudly listing the declared plugins (preserves fail-fast; also lets a user already write `gait_sequencer: adaptive_gait` if they want) |
| `mpc.type` | `"acados_mpc"` |
| `slc.type` | `"bezier_swing"` |
| `wbc.type` | `USE_WBC ? "wbc_arc_opt" : "inverse_dynamics"` (compile-time, mirrors `WBCType`) |
| `model_adaptation.type` | from legacy `ma_mode`: `1`→`rls_adaptation`, else `kf_adaptation` |

Implement the derivation as one small **string→string** free function (e.g.
`LegacyStageTypeDefault(stage, node params…)`) in a header the tests can include. This is *not*
a "concrete algorithm factory if/else" — it never names a C++ type, only pluginlib lookup
strings — and it is the swappable mapping layer the Kennel Console spec also assumes. Mark it
with a comment: introduced M2.4, vocabulary owned by #10 (M2.5), removal tracked by #23 (M5.4).
If the user sets `gs.type` etc. explicitly, the explicit value wins (it is simply the declared
parameter's value; the derivation only supplies the default).

### 3.2 Host members

In `mit_controller_node.hpp`, replace the five algorithm members:

```cpp
// Loaders declared BEFORE the instances they produce (destruction order, see stage_loader.hpp).
StageLoader<GaitSequencerInterface>      gs_loader_{stage_plugin_bases::kGaitSequencer};
StageLoader<MPCInterface>                mpc_loader_{stage_plugin_bases::kMPC};
StageLoader<SwingLegControllerInterface> slc_loader_{stage_plugin_bases::kSwingLegController};
StageLoader<WBCType>                     wbc_loader_{kWbcBaseString};   // see below
StageLoader<ModelAdaptationInterface>    ma_loader_{stage_plugin_bases::kModelAdaptation};

StageLoader<GaitSequencerInterface>::PluginPtr      gs_;
StageLoader<MPCInterface>::PluginPtr                mpc_;
StageLoader<SwingLegControllerInterface>::PluginPtr slc_;
StageLoader<WBCType>::PluginPtr                     wbc_;
StageLoader<ModelAdaptationInterface>::PluginPtr    ma_;
```

with `inline constexpr const char* kWbcBaseString = USE_WBC ? stage_plugin_bases::kWBC
: stage_plugin_bases::kWBCCartesian;` (or an `if constexpr` helper). `WBCType` stays exactly
`std::conditional<USE_WBC, WBCInterface<JointTorqueVelocityPositionCommands>,
WBCInterface<CartesianCommands>>::type`. Every call site (`gs_->…`, `mpc_->…`, etc.) compiles
unchanged because `StagePlugin<I>` *is* an `I`.

Note: loader construction can throw `StageLoadError` (package/XML problems). Let it propagate
out of the constructor; wrap node construction in `main()` in a try/catch that logs
`e.what()` before rethrowing/exiting non-zero, so bring-up failures are readable (fail-fast,
never a fallback).

### 3.3 `MakeStageInit()`

New private helper building the `StageInit` for each `Load` call (called only after the
existing "wait for first `/quad_state`" spin loop, so model/state are valid snapshots — same
guarantee construction has today):

```cpp
StageInit MITController::MakeStageInit() const/*-ish*/ {
  StageInit init;
  init.model = std::make_unique<QuadModelPino>(quad_model_);
  init.state = std::make_unique<QuadState>(quad_state_);
  const auto names = this->list_parameters({}, rcl_interfaces::srv::ListParameters::Request::DEPTH_RECURSIVE).names;
  for (const auto& n : names)
    init.params.emplace(n, this->get_parameter(n).get_parameter_value());
  return init;
}
```

Full param map per stage (a stage reads what it documents, ignores the rest —
`plugin_lifecycle.md` §3). Cost is startup-only (§6).

### 3.4 Constructor refactor

Keep the constructor's structure and ordering **identical**; only swap the construction block:

1. Parameter declarations: **keep them all as-is for M2.4** (including the stage-specific ones
   like `mpc_alpha`, `wbc.arc_opt.*`, `adaptive_gait_sequencer.*`). Rationale: rclcpp needs
   declarations for YAML values to be readable at all, the declared defaults must keep matching
   plugin-side `GetOr` defaults, and moving to
   `automatically_declare_parameters_from_overrides(true)` changes type-inference behavior for
   YAML integers (e.g. `mpc_fmax: 200` would arrive as int64 and make the plugin's
   `Require<double>` throw). Shrinking the declaration surface belongs with the YAML schema work
   in M2.5/#21, not here. Add the five `*.type` declarations (§3.1) next to `gait_sequencer`/
   `ma_mode` with a pointer comment to #10.
2. PD-gain loading, target prep, callback groups, publishers/subscribers, heartbeat, parameter
   callbacks: unchanged.
3. Delete the two `assert(typeid(wbc_.get()) == …)` blocks (:185-202). They run before `wbc_`
   exists, compare static pointer types (vacuous), and the real mismatch protection is the
   runtime-checked `solve_and_publish` error path from M1.2. Say so in the changelog.
4. After the first-quad-state spin loop, replace all five factories with:
   ```cpp
   gs_  = gs_loader_.Load("gs.type", MakeStageInit());
   mpc_ = mpc_loader_.Load("mpc.type", MakeStageInit());
   ma_  = ma_loader_.Load("model_adaptation.type", MakeStageInit());
   slc_ = slc_loader_.Load("slc.type", MakeStageInit());
   wbc_ = wbc_loader_.Load("wbc.type", MakeStageInit());
   gs_->UpdateTarget(target_);   // keep, same position as today
   ```
   Order: keep today's construction order (gs, mpc, ma, slc, wbc) to keep the diff reviewable.
   Errors: let `StageLoadError`/`StageInitError` propagate (see §3.2) — this *replaces* the old
   `RCLCPP_ERROR + rclcpp::shutdown()`/`exit(-1)` paths and is strictly more informative
   (loader errors list the declared alternatives).
   Keep `use_model_adaptation_` semantics exactly: the MA plugin is always loaded (as the
   concrete MA always was), the bool only gates the MA callback body.
5. Leg-driver mode service call, subscriptions, `mpc_loop_timer_`, `model_adaptation_loop_timer_`:
   unchanged, same order.

### 3.5 Runtime reconfiguration path

In the parameter-event callback, the per-stage `SetParameter` routing already goes through the
frozen interfaces — unchanged. The **gait-sequencer rebuild fallback** (:396-408) is the only
place that called a factory; replace with the loader (the `plugin_lifecycle.md` §5 swap
pattern — build off-loop, swap under lock, destroy old after release):

```cpp
if (gait_update) {
  auto fresh = gs_loader_.Load("gs.type", MakeStageInit());  // off-loop: resolve+create+Init
  fresh->UpdateTarget(target_);                              // mirror bring-up
  gait_sequencer_lock_.lock();
  gs_.swap(fresh);
  gait_sequencer_lock_.unlock();
  // `fresh` (now the old instance) destroyed here, outside the lock
}
```

Wrap in try/catch (`StageLoadError`/`StageInitError` → `RCLCPP_ERROR`, keep the old instance)
— a runtime reconfig failure must not kill a walking robot; matches today's `if (gs)` guard.

## 4. Long-term alignment (why this shape)

- **M2.5 (#10):** the `*.type` params are already the proposed vocabulary; M2.5 only writes
  explicit keys into the two Go2 YAMLs and documents them — no host change. The legacy
  derivation keeps `Depends on M2.4 (or land together)` satisfiable in either order.
- **M2.6 (#11):** this PR's human test plan (§7) is a dry run of the M2.6 gate; M2.6 stays the
  formal milestone exit and gets run after M2.5 lands.
- **M3.1 (#12):** contact FSM untouched in `ControlLoopCallback`, exactly where M3.1 expects it.
- **M3.2 (#13):** `WBCType`/`USE_WBC` compile-time split preserved; the only WBC-related change
  is who constructs it. `kWBCCartesian` base keeps the ULab build working.
- **M4 (#16-#19):** a third-party stage becomes selectable by setting `gs.type` (etc.) to its
  class name — the host has no allowlist; defaults are the only stock-name mentions.
- **M5.4 (#23):** the legacy `gait_sequencer`/`ma_mode` derivation is the "monolithic factory
  path" remnant; it is one small function, marked for deletion there.

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| A plugin `Init` default silently diverges from a host `declare_parameter` default | Keep all host declarations (§3.4.1); the YAMLs set the important keys anyway; M2.5/#21 unifies the vocabulary. Spot-check the five `Init` bodies against the deleted factory code during review. |
| Loader/Init throw during bring-up where the old code logged + shutdown | Intentional (fail-fast contract); `main()` catch makes it readable. Test T7/T8 in §7 covers it. |
| Reconfig swap leaves robot without GS on failure | Catch-and-keep-old (§3.5). |
| Plugin `.so` built at lower optimisation than the node was | Already handled in M2.3 CMake (plugins inherit directory-scope `-Ofast`/`-O3`); re-verify flags in build log. |
| `ROBOT_MODEL` define missing in plugin TUs | Verification step in §3.7. |
| Node link-prune breaks ulab build | Build both `-DROBOT_NAME=go2` and `ulab` (T1). |

## 6. Performance: why there is no loss, and how it is proven

**Analysis (goes in the PR):**
- All new work is **startup-only**: five `dlopen`s, five param-map copies (~100 entries each),
  model/state clones — all before any control timer exists. Steady-state loop bodies
  (`MPCLoopCallback`, `SLCLoopCallback`, `ControlLoopCallback`, `ModelAdaptationCallback`) are
  **not edited** by this refactor; the diff must show them untouched.
- The only steady-state delta: each stage call crosses the M2.3 adapter, adding one forwarding
  virtual call (~1-2 ns) on top of the virtual call that already existed through the interface
  pointer. Against 100 Hz/500 Hz loops whose work is multi-ms QP solves, this is below
  measurement noise. No allocation, no extra locking, no copies are added anywhere on the hot
  path.
- Plugin libraries compile with the same Release flags as the node (see §5).

**Measurement (do before opening the PR, include numbers):**
1. Baseline on `feature/modularization_central`, candidate on the PR branch, same Docker image,
   same machine, sim Go2, same scenario (≥60 s stand + ≥60 s trot at fixed target velocity).
2. Record `/solve_time` (`MPCDiagnostics.solve_time`, `acados_total_time`), `/wbc_solve_time`
   (`WBCReturn.total_time`), and the final `controller_heartbeat` counters
   (`num_mpc_solver_overtime`, `num_wbc_overtime`, `num_*_solver_fail`).
3. Compare mean/p95/p99 per phase. Pass: within run-to-run noise (re-run baseline twice to
   establish noise) and no counter grows faster than baseline. Report the table in the PR.
   (`ros2 topic echo --csv` + a scratch script, or `ros2 bag record` both runs, is fine.)
